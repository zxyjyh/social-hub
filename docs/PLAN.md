# 执行方案

## 时间线

| 时点 | 做什么 |
|---|---|
| **今天 · 30 分钟** | 提交 GBP Basic API Access + 启动 Meta Business Verification，两队列并行 |
| **第 1 天 · 1 小时** | 跑完下面的验证清单，**先做这个再写代码** |
| **第 1 周** | 三个接口 + Meta OAuth + FB 发布跑通<br>验收：后台点一下，自己的 Page 上真的出现帖子 |
| **第 2 周** | IG 容器发布 + 接内容生成 + 评论托管 + 数据看板<br>Google 适配器按接口写好接 mock<br>**开始给自己的主页真实供稿** |

| **48 小时** | 不做新功能，把两周成果串成能连贯讲完的线 |

赛中不是从零开始写，这是整个方案成立的前提。

## 开工前的验证清单

任何一条答案不对，方案的形状就要改。

- [ ] **自己有没有 FB / IG 主页？最后更新是什么时候？**（10 分钟）
      「三年前发过两条」→ 问题陈述成立。维护得挺好 → 第一个客户要换
- [ ] **抽 20 家签约商家看有没有 Page、更新频率**（40 分钟）
      有 Page 但半年没更新 → 有痛点
      压根没 Page → 价值主张换成「用 AI 内容工厂换授权」
      更新得挺勤 → **没有痛点，换题**
- [ ] **GCP Console → Quotas 查 Business Profile API 配额**（5 分钟）
      0 = 没批；300 = 早就批过，Google 那半边立刻能做真的
- [ ] **问一句：有没有人已经在做社媒相关的？**（半小时）
      重复造已存在的东西，比做错方向更伤

## 演示脚本 · 5 分钟

1. **问题陈述** —— 投屏打开自己的主页，指着「最后更新：X 个月前」
2. **绑定** —— 后台点「绑定公域账号」，走完 OAuth，主页进列表。十几秒
3. **生成** —— 选一家真实门店和在售团单，AI 出图文（有多语言就同时出两版）
4. **发布** —— 点发布，切到 Facebook，帖子在那儿
5. **评论托管** —— 事先安排人留言「几点打烊」，后台拉到评论，
   AI 起草，**你点确认**，回复发出。强调这一步是人确认的
6. **看板** —— 曝光、互动、单条表现
7. **路线图** —— 「Google 适配器已写好，在等配额。往后任何平台，三个接口」

**如果配额批下来了**，把第 4 步换成 Google：请评委掏出手机用 Google Maps
搜那家店，刚发的帖子就在上面。这是全场唯一一个评委能自己验证的演示。

**如果没批**，走 Meta-only，但必须提前把评委加成 App 的 tester 角色，
否则他们刷不到。

## 台上要主动说的四件事

1. **开发模式的可见性限制** —— 主动说是做过功课，被问出来是掉分
2. **Google 在排队** —— 主线本来就不依赖它，批了是加分
3. **刻意没做自动互动** —— 「我们没做什么」比「做了什么」更证明判断力
4. **「内地客占多数做这个有什么意义」** —— 用数字答：
   2025 年入境 4006.9 万人次，港台加国际客 1094 万、占 27%。
   但主线不是他们的流量，是底座能力：今天是 Facebook，
   往后可以是内地客真正在用的任何平台，只要它有官方 API

## 止损判据

一份 592 个项目的研究显示，65% 的黑客松项目结束即停，5 个月后仅 3.55% 仍活跃，
且「赢奖 → 长期延续」这个假设在长期模型中被明确拒绝。

**赛后 4 周内，有没有带预算的组织单元主动接洽？**
没有、且自己也没做扩散，第 4 周止损。
同一研究还发现：赛后第一周高频提交与长期延续**负相关**——
那是在打磨原型，不是在找归属。
